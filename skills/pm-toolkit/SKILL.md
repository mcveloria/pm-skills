# PM Toolkit

Pick the template that fits, ask only for missing essentials, fill it with the user's context, and flag open questions rather than inventing facts. Keep documents short: if a section has nothing real, cut it.

## PRD (product requirements doc)

```
Title / owner / status / last updated
1. Problem and context: who, what pain, evidence (data, quotes)
2. Goals and success metrics (with baseline and target)
3. Non-goals
4. Users and use cases (key scenarios)
5. Solution overview: flow, wireframe links
6. Requirements: numbered, prioritized (P0/P1/P2), testable
7. Edge cases, error states, permissions, accessibility, i18n
8. Analytics: events to track
9. Rollout: phases, flags, migration, support/training
10. Risks, dependencies, open questions
11. Timeline and milestones
```

## User story

`As a [persona], I want [capability], so that [outcome].`
Acceptance criteria in Given/When/Then:
`Given [context], when [action], then [observable result].`
Check INVEST: Independent, Negotiable, Valuable, Estimable, Small, Testable. Split large stories by workflow step, rule, data variation, or happy path first.

## One-pager (pitch)

Problem, who it affects, proposed solution, expected impact (metric), effort estimate, risks, ask (decision needed by when).

## Stakeholder update

```
TL;DR (2 lines, status: green/yellow/red)
Progress since last update
Next up
Risks / blockers (with owner and ask)
Decisions needed
Metrics snapshot
```

## Decision log entry

Date, decision, context, options considered, rationale, owner, revisit date.

## Meeting notes

Attendees, agenda, decisions, action items (owner + due date), open questions. Send within 24 hours.

## Release notes

Lead with user benefit, not implementation. Group: New, Improved, Fixed. One sentence each plus a link.

## Retro formats

Start/Stop/Continue; 4Ls (Liked, Learned, Lacked, Longed for); Sailboat. End with at most 3 committed actions with owners.

## Writing rules

Lead with the conclusion. Use concrete numbers and dates. One idea per paragraph. Replace jargon with plain words. Make asks explicit ("Decision needed from X by Friday").

## Quick prioritization worksheet

Columns: item, reach, impact, confidence, effort, score, notes. Sort descending, then sanity-check against strategy.
