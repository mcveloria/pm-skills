# Product Strategy

A strategy is a coherent set of choices about where to play and how to win, with explicit trade-offs. If nothing is ruled out, it is a wish list.

## Workflow

1. **Diagnose** the situation: customers, market, competitors, internal strengths, constraints. Name the one or two critical challenges.
2. **Set direction:** vision (3-5 years, customer-centered), mission, and a north star metric with input metrics.
3. **Choose a guiding policy:** target segment, value proposition, differentiation, what we will not do.
4. **Translate to goals:** company OKRs → product OKRs.
5. **Prioritize** bets with a scoring model.
6. **Roadmap** by outcomes and time horizons (Now / Next / Later), not feature dates.
7. **Communicate and revisit** quarterly.

## Strategy doc skeleton (Rumelt kernel)

```
1. Diagnosis: what's going on and why it's hard
2. Guiding policy: our approach and key trade-offs
3. Coherent actions: bets, sequencing, owners
4. Success measures and leading indicators
5. Risks, assumptions, kill criteria
6. What we are explicitly not doing
```

## Positioning (April Dunford)

Competitive alternatives → unique attributes → value those enable → who cares most → market category. Output a positioning statement: `For [target] who [need], [product] is a [category] that [key benefit]. Unlike [alternative], we [differentiator].`

## Prioritization tools

| Tool | Use when |
|---|---|
| RICE (Reach x Impact x Confidence / Effort) | Many comparable features, some data |
| ICE | Fast scoring of experiments |
| Kano | Separating must-haves from delighters |
| Value vs effort 2x2 | Quick workshop alignment |
| Weighted scoring | Aligning to strategic themes |
| Cost of delay (WSJF) | Time-sensitive trade-offs |

Always show the scores' inputs and sensitivity. A score is a conversation starter, not the decision.

## OKRs

Objective: qualitative, inspiring, time-bound. 2-4 key results: measurable outcomes (not outputs), ambitious but 60-70% attainable. Example KR: "Raise week-4 retention from 28% to 35%" not "Ship onboarding v2".

## Roadmap rules

- Organize by problem/outcome and confidence horizon: Now (committed), Next (planned, scoped), Later (explored).
- Include rationale, target metric, and dependencies per item.
- Tailor views: exec (themes), team (details), customer-facing (no dates).

## Build / buy / partner

Build if core differentiator; buy or partner if commodity, time-critical, or outside core skills. Compare total cost (including maintenance), time to value, lock-in, and strategic control.

## Outputs

Vision brief, strategy one-pager, OKR set, scored backlog, Now/Next/Later roadmap, positioning doc, north star tree, strategy review agenda.

## Pitfalls

Feature-factory roadmaps, strategy as a list of goals with no choices, too many priorities (cap at 3), metrics that can be gamed, ignoring capacity and dependencies.
